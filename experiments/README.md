# 첫 기준 실험 따라가기

목표는 높은 점수 하나를 얻는 것이 아니라, **어떤 입력으로 어떤 미래를 예측했고 어떻게 시험했는지 설명할 수 있는 실험**을 만드는 것입니다.

## 1. 질문을 한 문장으로 고정

“이미 트렌딩에 진입한 이벤트가 관측 기준 48시간 이상 지속할까?”를 묻습니다.
입력 `X`는 진입 때 아는 정보, 정답 `y`는 시간이 흐른 뒤 확인한 0 또는 1입니다.
예를 들어 진입 조회수가 10만이고 60시간 관측된 이벤트는 `T0_view_log`가 입력, 정답 1이 됩니다.
60시간이라는 값을 입력에도 넣으면 정답을 알려주고 시험하는 셈입니다.

`src/trendit_lab/data.py`는 입력 허용 목록을 검사하고 저장된 피처와 라벨을 재계산합니다.
분석용 파일을 읽더라도 모델에 넘기는 열은 허용 목록으로 다시 제한합니다.

## 2. 먼저 분할하고, 그다음 학습

```text
2022~2023년                 2024년                     2025년
학습(train)                검증(validation)           최종 시험(test)
전처리 통계·가중치를 학습 → 세 모델 중 하나를 선택 → 선택한 모델을 평가
```

검증은 연습 시험, 최종 시험은 답을 보고 전략을 바꾸지 않는 평가 자료입니다.
이 실험은 검증에서 모델을 고른 뒤 학습+검증으로 다시 학습하지 않습니다.
그래야 고른 모델과 최종 평가 모델이 같은 상태를 유지합니다.

경계가 2024년 1월 1일이라면, 2023년 12월 31일 진입 영상의 48시간 뒤 결과는 아직 모릅니다.
이 행을 학습에 쓰면 미래 정답을 미리 사용합니다. 따라서 `T0 + 48시간 + 6시간 < 다음 경계`인 행만 씁니다.
6시간은 수집 주기 하나를 여유로 둔 보수적인 설계 선택입니다. 54시간 경계와 정확히 같은 행도 제외합니다.
0과 1에 같은 규칙을 적용해 결과에 따라 학습 대상을 고르는 편향을 줄입니다.

동일 영상이 2023년과 2024년에 모두 나오면 2024년 이벤트를 제외합니다.
이전 기간에서 다른 이유로 제외된 영상도 “이전에 관측된 영상”으로 취급합니다.
채널까지 분리하지는 않으므로 새 채널 성능을 주장할 수는 없습니다.

## 3. 전처리도 학습이다

수치 피처는 `StandardScaler`, 카테고리는 `OneHotEncoder`로 변환합니다.
Scaler는 학습 데이터에서 평균·표준편차를 구합니다. 검증·시험에서는 그 값을 그대로 사용합니다.
검증 세트에서 평균을 다시 구하면 학습과 다른 좌표계가 되며, 전체 데이터를 먼저 스케일링하면 미래 분포를 미리 본 것입니다.

`Pipeline`은 전처리와 모델을 한 묶음으로 만들고 `fit`/`predict_proba` 호출 순서를 일관되게 유지합니다.
One-hot encoding은 카테고리를 각각 0/1 열로 표현합니다. 학습에 없던 카테고리는 오류 대신 0 벡터로 처리합니다.
숫자형 요일은 첫 실험에서 단순하게 그대로 사용합니다. 요일 인코딩 변경은 나중의 비교 실험으로 남깁니다.

## 4. 세 모델을 같은 조건으로 비교

| 모델 | 역할 |
|---|---|
| Dummy(prior) | 입력을 무시하고 학습 세트의 양성 비율을 확률로 출력. 최소 비교 기준 |
| 로지스틱 회귀 | 입력의 가중합에서 0~1 확률을 추정하는 단순 분류 모델 |
| 랜덤포레스트 | 여러 결정트리의 예측을 모아 비선형 관계를 표현하는 모델 |

세 모델은 같은 행·입력·정답·임계값을 사용합니다. 복잡한 모델이라고 반드시 더 좋아지는 것은 아닙니다.
모델 설정은 실행 전에 `configs/baseline.toml`에 고정했습니다. 이번에는 대규모 하이퍼파라미터 탐색을 하지 않습니다.

확률 0.7은 모델이 정답 1 쪽에 더 무게를 둔다는 뜻입니다. 확률이 0.5 이상이면 1로 판정합니다.
이 확률이 실제 빈도와 잘 맞는지(보정)는 별도 문제이며, 이번 결과만으로 정확한 확률이라고 단정하지 않습니다.

## 5. 정확도 하나로 고르지 않기

실제 정답 1이 70%인 자료에서 항상 1이라고 하면 정확도는 70%입니다. 입력을 읽지 않아도 가능합니다.
Balanced accuracy는 정답 0의 재현율과 정답 1의 재현율을 평균하므로 이 모델은 0.5입니다.
검증 balanced accuracy가 가장 높은 모델을 선택합니다. 동률이면 Dummy → 로지스틱 → 포레스트 순서입니다.

정밀도는 “1이라고 한 것 중 실제 1 비율”, 재현율은 “실제 1 중 찾아낸 비율”, F1은 둘의 조화평균입니다.
ROC AUC와 AP는 확률 순위, log loss와 Brier score는 확률 예측의 오차를 평가합니다.
AP는 average precision이며 사다리꼴 적분으로 구하는 PR AUC와 구별합니다.
시험에서는 선택 모델과 Dummy만 계산해 시험 세트로 후보를 다시 고르는 일을 피합니다.

## 6. 결과 파일 읽는 순서

1. `report.md`: 데이터 수, 검증·시험 점수, 한계.
2. `metrics.json`: 반올림 전 지표와 혼동행렬. `[[TN, FP], [FN, TP]]` 순서.
3. `split_assignments.csv`: 모든 이벤트의 소속 또는 제외 이유.
4. `validation_predictions.csv`, `test_predictions.csv`: 행별 정답과 예측 확률.
5. `audit.json`, `schema.csv`: 데이터 검증 요약과 열 구조.
6. `manifest.json`, `config.toml`: 데이터/소스/설정 해시, Python·라이브러리 버전, Git 상태.

실행 디렉터리는 Git에서 제외합니다. 첫 실행의 요약·지표·감사·manifest는 `reports/baseline_v1*`로 별도 보관합니다.
모델 파일은 저장하지 않습니다. 학습 코드와 설정, 데이터로 다시 학습해 예측을 재현하는 방식입니다.
원본 Parquet와 기초 노트북은 이 실험에서 변경하지 않습니다.

- 검증 결과만 보고 `min_samples_leaf` 변경을 제안하고, 왜 바꾸는지 실행 전에 적어보세요.
- 변경 실험은 별도 설정·출력 디렉터리에 저장하세요. 기존 시험 결과를 봤다면 이후 결과는 탐색이라고 표시하세요.

## 후속 실험 순서

1. 24시간 관측 가능한 동일 이벤트 집합에 현재 분할을 적용해 T0와 T0+24h 입력 비교.
2. 시간 구간을 여러 개로 옮기는 검증으로 특정 연도에만 결과가 좋은지 확인.
3. 영상별 묶음을 고려한 불확실성 추정, 새 채널을 별도로 제외한 평가.
4. 필요가 확인된 경우에만 임계값·모델 설정·딥러닝 확장.

원시 수집 데이터 확보 후에는 수집 누락과 실제 최초 진입 여부까지 검증하는 것이 별도 과제입니다.
